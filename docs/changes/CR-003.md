## 1. Problem Statement
When staff operators attempt to authenticate via the production deployment (`https://gocar-staff.pages.dev`), the login fails silently with no error feedback.

### Root Causes
1. **Cross-Origin Cookie Dropping**:
   - The staff interface is hosted on Cloudflare Pages (`gocar-staff.pages.dev`), while the API backend is on Render (`gocar-backend-crtx.onrender.com`).
   - The backend was setting cookies with `sameSite: 'lax'`. Browsers strictly reject cross-site `SameSite=Lax` cookies on asynchronous fetch/Axios requests.
2. **Missing Bearer Token Interceptor in Staff Interface**:
   - Unlike `customer-portal` (which attaches `Authorization: Bearer <token>` from `localStorage`), `staff-interface` had its request interceptor removed and relied exclusively on cookies.
3. **Silent Redirect Loop on 401**:
   - `staff-interface/src/utils/api.js` automatically redirected to `window.location.href = '/login'` upon encountering a 401 response on any route, resetting state before the error toast could be seen.
4. **HTML5 Email Input Constraint & Identity Mismatch**:
   - The login form input was set to `type="email"` and required an email format, blocking single-word usernames (e.g. `admin`) at the browser validation level.
   - The backend controller matched only against `users.email`, rejecting valid username inputs or email variations.
5. **Render Free-Tier Cold Starts**:
   - Render instances spin down after inactivity, causing initial network delays of 15–30 seconds. Unhandled network timeouts appeared as silent failures.

---

## 2. Blast Radius & Impact Assessment
- **Backwards Compatibility**: 100% backwards compatible. Dual auth mechanism supports both HTTP-only cookies and standard `Authorization: Bearer` headers.
- **Affected Endpoints**:
  - `POST /api/auth/staff/login`
  - `POST /api/auth/logout`
  - Protected API routes requiring `verifyToken`
- **Security Impact**: Zero security degradation. Tokens continue to be signed with HMAC-SHA256 (`JWT_SECRET`), expiration enforced at 7 days, and passwords hashed with `bcrypt`.

---

## 3. Implementation Plan
1. **Dual Token Transport**:
   - In production, set cookies with `SameSite=None` and `Secure=true`.
   - Update `staff-interface` to save the issued token in `localStorage` and transmit `Authorization: Bearer <token>` on all requests.
2. **Flexible Staff Identifier**:
   - Update `staffLogin` in `controllers/authController.js` to accept `email`, `username`, or `identifier` (`LOWER(email) = LOWER(?) OR LOWER(name) = LOWER(?) OR email LIKE ?`).
3. **Resilient UI & Cold-Start Visibility**:
   - Update `staff-interface/src/components/Login.jsx` to `type="text"`.
   - Add visual cold-start timer indicator when requests exceed 3 seconds.
   - Format network connection failures with clear retry guidance.
