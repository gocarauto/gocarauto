# CR-001: Deduplication of Due Maintenance Reminders

## 1. Overview & Intake
- **Change Request ID**: CR-001
- **Target Component**: Due Maintenance Reminders (`service_reminders` table, `reminderController.js`, `financialController.js`, `cron.js`, `ServiceRemindersModule.jsx`)
- **Severity**: High (Affects operational workflow, customer communications, and UI clarity)
- **Status**: Implemented & Verified
- **Intake Summary**: In the Active Maintenance Reminders view, multiple identical reminder rows appeared for the same client and vehicle (e.g. Ahmad Mohy with Mitsubishi Colt appeared 3 times with due date 3 Nov 2026; Ashraf Shalaby appeared twice).

---

## 2. Root Cause Analysis
1. **Schema Vulnerability**: The `service_reminders` table lacked a unique index or constraint on `(vehicle_id, service_type)` for `Pending` reminders.
2. **Type String Drift across Controllers**:
   - `scripts/cron.js` previously inserted English tracking types (`ENGINE_OIL`, `TRANS_OIL`).
   - `controllers/financialController.js` previously inserted `tracking_point` (`ENGINE_OIL`) or raw invoice item strings (e.g. `Maintenance`, `زيت موتور رزويل 10000`).
   - `controllers/reminderController.js` inserted Arabic labels (`تغيير زيت الموتور`, `تغيير زيت الفتيس`).
   - Because `existing` checks evaluated literal string matches against only one or two variants, differently named oil reminders for the same vehicle were inserted multiple times.
3. **Frontend Label Normalization**:
   - `ServiceRemindersModule.jsx` normalizes all oil-related variations (`ENGINE_OIL`, `زيت موتور رزويل 10000`, etc.) to `تغيير زيت الموتور`. This masked the differing underlying database strings, causing them to render identically in the table.
4. **Un-deduplicated Query**:
   - `getAllReminders` queried `SELECT r.* ... FROM service_reminders` with a simple `WHERE r.status = 'Pending'`, returning all redundant rows directly.

---

## 3. Impact & Risk Assessment
- **Side-Effect Classification**: Production Changes / Data Remediation
- **Database Reversibility**: Reversible via timestamped database backup (`database/gocar_auto.db.bak_20261102_182804`).
- **Workflow Impact**: Eliminates redundant WhatsApp dispatch triggers, eliminates duplicate follow-up calls, and restores accurate badge counts (122 reduced to exactly 70 unique active pending reminders).

---

## 4. Remediation Architecture & Implementation
1. **Canonical Service Normalization**:
   - Implemented `canonicalizeServiceType(type)` in `utils/maintenance-helper.js` standardizing all service variants (Arabic phrases, English keys, specific oil brand names) into canonical Arabic category strings.
2. **Database Cleanup & Migration**:
   - Created and executed `scripts/dedup-reminders.js`.
   - Deleted 52 redundant duplicate rows across 45 vehicle groups.
   - Standardized 12 reminder labels to canonical names.
   - Enforced SQLite partial unique index:
     ```sql
     CREATE UNIQUE INDEX IF NOT EXISTS idx_unique_pending_vehicle_service 
     ON service_reminders(vehicle_id, service_type) 
     WHERE status = 'Pending';
     ```
   - Updated `database/schema.sql` with this index definition.
3. **Backend Controllers Alignment**:
   - `controllers/reminderController.js`: Canonicalizes service types on `checkDuplicate`, `createReminder`, `runSmartScan`, and applies defensive deduplication in `getAllReminders`.
   - `controllers/financialController.js`: Canonicalizes service types before checking existence and inserting reminders from paid invoices.
   - `scripts/cron.js`: Uses `canonicalizeServiceType` in the daily 9:00 AM smart scanner.
4. **Frontend Defense-in-Depth**:
   - Updated `staff-interface/src/components/ServiceRemindersModule.jsx` with client-side deduplication filtering in `fetchReminders`.
5. **Automated Regression Test**:
   - Added `tests/reminder-dedup.test.js` verifying canonicalization logic and confirming the database unique index actively rejects duplicate pending insertions.

---
