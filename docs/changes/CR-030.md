# Change Request CR-030: Real Vehicle Telemetry Integration for Customer Portal Dashboard (Engine & Transmission Oil Life)

- **Date:** 2026-11-22
- **Phase:** Phase 10 (Change Requests)
- **Role:** Builder & Scribe
- **Status:** Complete & Verified
- **Tooling / Verification:** `npm run verify` (60 passing tests, 0 ESLint errors, 2 clean Vite production builds)

## Objective
Replace synthetic placeholder math (`10000 - (mileage % 10000)`) and hardcoded static numbers (`activeVehicle.services_count > 0 ? 92 : 100`) on the Customer Portal vehicle cockpit HUD sketch with real automotive fluid telemetry dynamically computed from GoCar Auto's database service records, odometer logs, and maintenance reminders.

## Scope of Changes

1. **Automotive Telemetry Engine (`utils/vehicleTelemetry.js`):**
   - Engineered a pure, deterministic calculation engine evaluating vehicle fluid degradation based on:
     - **Distance Decay:** Measures kilometers driven since last oil service against rated intervals (e.g. 5,000 km, 7,000 km, 10,000 km for engine oil; 30,000 km – 50,000 km for transmission fluid).
     - **Temporal Decay:** Measures calendar months elapsed since last service date against fluid life expectancy (e.g. 8 months for engine oil; 24 months for transmission fluid).
     - **Limiting Factor Principle:** Following automotive standards (e.g., GM/Honda/Ford OLM systems), fluid life is determined by `Min(Mileage Life, Time Life)`, with an initial 15-day / 50 km grace window for brand-new services preserving 100%.
     - **Status Classification:** Automatically categorizes fluid status into `good` (>30%), `warning` ($\le 30\%$), `critical` ($\le 10\%$ or overdue), and `untracked` (for vehicles registered without workshop service records yet).
     - **Data Normalization:** Robust parsing for ISO strings, Date objects, Unix timestamps, and legacy Excel serial numbers (e.g. 45489).

2. **Customer Portal Controller Enrichment (`controllers/customerPortalController.js`):**
   - Added `enrichVehiclesWithTelemetry(vehicles)` helper that performs batch querying ($O(1)$ database trips) for itemized service records and pending reminders.
   - Enriches all vehicle objects returned by `/api/customer-portal/vehicles` and `/api/customer-portal/dashboard` with a complete `telemetry` object (`engine_oil` and `transmission_oil`).
   - 100% backward-compatible with existing vehicle schema attributes.

3. **Customer Portal Cockpit HUD & Garage Fleet Cards (`Dashboard.jsx` & `VehicleFleet.jsx`):**
   - **Desktop Cockpit HUD (`Dashboard.jsx`):**
     - Point A (Left Capsule): Binds Engine Oil Life directly to `telemetry.engine_oil`, featuring dynamic health-state status dot, progress bar, exact percentage or `—%`, and contextual subtitle (`Next due in ~X km` or `Inspection recommended`).
     - Point C (Right Capsule): Binds Transmission Oil Life to `telemetry.transmission_oil`, eliminating the static 92% and rendering true remaining distance or scheduled verification.
     - Dynamic HUD SVG laser leader lines: Glow stroke dynamically adapts to fluid health state (Rose for critical, Amber for warning, Cyan/Emerald for good, Slate for untracked).
   - **Mobile Vitals Tray:**
     - Synchronized mobile cards beneath the stage with the exact same real vehicle metrics, colors, and bilingual labels.
   - **My Vehicles / Garage Fleet Cards (`VehicleFleet.jsx`):**
     - Bound Dual Health Capsules (Box 4) across all vehicle executive showcase cards to `v.telemetry.engine_oil` and `v.telemetry.transmission_oil`.
     - Displays true percentage, status colors (Emerald, Amber, Rose, Slate), and progress bars matching the Dashboard HUD.

4. **Bilingual Localization (`customer-portal/src/utils/translations.json`):**
   - Added translations for `inspection_recommended` ("Inspection Recommended" / "يوصى بالفحص الأولي") and `scheduled_verified` ("Scheduled interval verified" / "تم التحقق من جدول الصيانة").

5. **Automated Verification Gate:**
   - Authored unit & integration tests (`tests/telemetry.test.js`): 11 tests covering date parsing, fluid classification, interval extraction, fresh service, distance decay, time decay, warning/critical thresholds, untracked fallback, and live controller response enrichment.
   - Verified that `npm run verify` runs cleanly with 60/60 passing tests, 0 ESLint errors, and successful production builds of both frontends.
